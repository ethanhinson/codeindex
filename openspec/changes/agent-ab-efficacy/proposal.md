## Outcome (2026-07-09) — VERDICT: RED

Ran ($7.89, 96 paired runs). **codeindex increased agent cost by ~17% (ITT) /
~26% (when actually used) with identical task success (89.6% both arms) despite
81% adoption.** Mechanism: the query is an additive round-trip and Claude's
native Grep is already cheap for these tasks, so the extra call doesn't pay for
itself; the more the tool was used, the worse the cost. Repo size did not flip
the sign. Full analysis and caveats in `bench/agent_ab/FINDINGS.md`.

Pre-registered RED action: **stop building breadth on the token-savings premise.**
The static 363× studies compared against reading whole files — a baseline real
Claude does not use. Honest limitation: the tasks tested are ones ripgrep already
handles cheaply (`rg -l`); the untested frontier is expensive/insufficient-grep
tasks (call-graph traversal, blast-radius, hot-name disambiguation). Next step is
to redesign the task set around those before any further engineering — not to
proceed to `core-indexing-engine` breadth, the resolver, or the plugin.

## Why

Every codeindex validation so far is **static token arithmetic**: we compared
the size of an index answer against the size of files an agent *hypothetically*
reads (median 363×, min 6×, across 109 real-issue symbols — see
`bench/efficacy-FINDINGS.md`). But the project's stated goal is that **a real
agent completes real tasks with fewer tokens and no loss of quality** — and that
depends on two things static analysis cannot measure: (1) whether the agent
actually *adopts* the tool mid-task instead of its ingrained Grep/Read habits,
and (2) whether compact reference answers are *good enough* that the agent
doesn't burn the savings on follow-up reads. This change builds the experiment
that measures the goal directly, with pre-registered decision thresholds that
gate the rest of the roadmap. It is deliberately scheduled before the full MVP
build: if the result is negative, we rethink before spending months on breadth.

## What Changes

- A new harness under `bench/agent_ab/` that runs **headless Claude Code**
  (`claude -p`) on a fixed task set, in two arms:
  - **Arm A (control):** standard tools only (Bash, Read, Grep, Glob).
  - **Arm B (treatment):** identical, plus documentation of the `codeindex`
    CLI injected via appended system prompt, and the prebuilt index available.
- A **task builder** that generates two objectively gradable task types from
  real repositories pinned in `bench/repos.json`:
  - **Comprehension:** "Where is symbol X defined (file:line)? List every file
    that references X." Ground truth generated by ripgrep (arm-neutral).
  - **Localization:** real closed GitHub issues whose linked merged PR provides
    ground truth ("which files must change to fix this issue?").
- A **runner** that executes each (task × arm × repetition) in an isolated,
  reset repo state, captures the full transcript, and records tokens, cost,
  turns, tool-call counts, and codeindex invocations.
- A **grader** (script-based, arm-blind) and a **report** generator producing
  paired-difference statistics with bootstrap confidence intervals, plus
  intent-to-treat and per-protocol (tool-actually-used) analyses.
- **Pre-registered decision thresholds** written down before the first full
  run, so the outcome cannot be retro-fitted.

Non-goals: no changes to the engine or index; no MCP server (arm B uses the
existing CLI via Bash — the MCP wrapper is a later change); no edit/fix tasks
in v1 (comprehension + localization only; an edit-task phase is a documented
stretch goal); no LLM-judge grading in v1 (objective script grading only).

## Capabilities

### New Capabilities

- `agent-ab-harness`: The A/B experiment — task generation with arm-neutral
  ground truth, isolated headless-agent execution in two arms, metric capture
  (tokens/cost/turns/tool calls/adoption), script-based grading, paired
  statistical analysis, and pre-registered decision thresholds.

### Modified Capabilities

None. (The `performance` spec of `core-indexing-engine` already notes that
end-to-end agent savings are measured by this change.)

## Impact

- New directory `bench/agent_ab/` (Python, consistent with existing `bench/`
  scripts); results under `bench/agent_ab/results/`.
- Consumes: the existing `codeindex` binary (built from this repo,
  `go build ./cmd/codeindex`), the pinned repo clones from `bench/repos.json`,
  the GitHub REST API (task building), and the locally installed `claude` CLI.
- Spends real API budget: estimated 50–200 USD for a full pre-registered run
  depending on model and repetitions; the design specifies cost-control knobs
  and a mandatory 2-task smoke run first.
- Produces the project's headline number: **median % reduction in total task
  tokens with no loss of task success**, plus the adoption rate that changes 2–4
  (query surface, resolution precision, plugin/skill design) will be steered by.
